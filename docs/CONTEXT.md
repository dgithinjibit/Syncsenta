# SyncSenta — Domain Glossary

This file is the single source of truth for domain language in this repo.
Every agent session should read it before writing code or specs.
Keep it as a **glossary only** — no implementation details, no specs, no scratch notes.

---

## The Product

**SyncSenta** (`studio/`) is an AI-powered Kenyan K–9 education platform.
It delivers CBC-aligned learning to students, gives teachers a real-time
analytics and intervention dashboard, and connects to parents and guardians.

Deployed at: **sentastudio.vercel.app**
Repo: **dgithinjibit/Syncsenta** (monorepo — `studio/` is the Next.js app)

---

## People

**Student** — a learner in a Kenyan school, PP1 through Grade 9. The primary
user of the learning canvas and chat tutor.

**Teacher** — a CBC-trained educator. Uses the teacher dashboard to monitor
students, generate schemes of work, lesson plans, and assessments. Must belong
to a classroom.

**Guardian** — a parent or carer linked to a student. Receives progress
reports and achievement notifications.

**Admin** — a school administrator. Has elevated access across classrooms.

## Curriculum

**CBC** — Competency-Based Curriculum. Kenya's official national curriculum,
introduced in 2017. Replaces the old 8-4-4 system. All content in SyncSenta
is CBC-aligned.

**CBC Level** — one of four bands: `pre-primary`, `lower-primary`,
`upper-primary`, `junior-secondary`. Defined in `lib/cbc-curriculum.ts`.

**Grade** — the specific year within a level. Full set:
`PP1`, `PP2`, `Grade 1`–`Grade 9`.

**Generalist grade** — PP1, PP2, Grade 1–3. One teacher covers all subjects.

**Specialist grade** — Grade 4–9. Subject-specific teachers.

**Strand** — a major topic within a subject (e.g. "Number" in Mathematics).

**Sub-strand** — a focused unit within a strand (e.g. "Fractions" within
"Number"). The granularity at which activities are authored and competencies
are tracked.

**Competency** — a measurable skill a student should demonstrate at a given
grade level. Identified by a code like `G2.MATH.NS.1` (Grade 2, Mathematics,
Number Sense, objective 1). Tracked in the `learning_progress` table.

**Term** — Kenya's school year has three terms. Activities are tagged by term
(1, 2, or 3). Controlled by `lib/term-utils.ts`.

**Scheme of work** — a teacher's term-long plan mapping strands, sub-strands,
lessons, and time. Generated by the scheme wizard (`/teacher/scheme-wizard`).

## Learning

**Activity** — a single learning task in the student sandbox. Has an `id`,
`grade`, `subject`, `type`, and optional `manipulative`. Defined in
`lib/sandbox-types.ts`. Catalogued in `lib/sandbox-activities.ts` and the
`curriculum/` folder.

**Activity type** — `explore`, `practice`, `challenge`, or `create`.

**Manipulative** — the interactive canvas type an activity uses:
`fraction-bars`, `tokens`, `shapes`, or `number-line`. Activities without a
manipulative render as generic worksheet (`GenericActivity`).

**Variation** — one question in a micro-assessment loop within an activity
(Synthesis-style mastery gating). A student must pass `masteryThreshold`
variations to mark the activity mastered.

**Mastery** — a student has mastered an activity when they pass the required
number of variations correctly. Stored in `learning_progress.mastery_level`.

**Resume point** — the last `currentActivity` stored in Redis for a student.
Records which activity, which variation index, and what progress percentage
they were at. Used to restore the canvas on return. Managed by
`lib/session-persistence.ts` and `/api/session/sync`.

**XP** (experience points) — points earned per subject, accumulated from
`point_transactions`. Used to compute a student's level per subject
(1–5). `getSubjectXP()` in `lib/subject-session.ts`.

**Level** — a student's XP tier within a subject. Thresholds: 200 XP → Level 2,
500 → Level 3, 1000 → Level 4, 2000 → Level 5.

## AI Tutor

**Omega agent** — SyncSenta's tutoring decision engine. Given a student's
learning state, it computes a scaffolding level before every chat response.
The TypeScript implementation lives in `lib/omega-agent/metta-core.ts`
(`evaluateTutoringDecision`). A Rust implementation exists in
`rust-core/src/agent_runtime.rs` but is not yet wired to production.

**LearningState** — the input to the Omega agent: `{ attempts, correctAttempts,
hintsUsed, frustrationSignal }`. Built from `learning_progress` rows by
`buildLearningState()` in `lib/subject-session.ts`.

**TutoringDecision** — the Omega agent's output: `{ scaffolding, hint,
nextAction }`.

**Scaffolding level** — one of three values that controls how the tutor
responds in a given turn:
- `Independent` — student is performing well (mastery ≥ 80%). Tutor asks
  open-ended questions, does not give the answer.
- `Guided` — student is developing (mastery 40–79% or no attempts yet).
  Tutor asks one guiding question per turn.
- `Intensive` — student is struggling (mastery < 40%, hintsUsed ≥ 2, or
  frustrationSignal). Tutor breaks concept into smallest possible steps,
  uses Kenyan examples.

**Dynamic system prompt** — the system prompt sent to the LLM, built by
`buildDynamicSystemPrompt()`. Replaces the old static socratic prompt. Includes
grade, subject, language, student name, scaffolding instructions, and hint.

**Chat session** — a persistent conversation thread between a student and the
AI tutor, scoped to one subject. Stored in the `chat_sessions` table with
`last_message_at` and `status = 'active'`. A session is reused for up to 30
days before a new one is created. `getOrCreateChatSession()` in
`lib/subject-session.ts`.

**Subject layout** — determines how the subject page renders. `chat` = full-
height embedded chat (blockchain, financial-literacy, ai). `sandbox` =
redirects to the activity list (core CBC subjects). Defined per slug in
`SUBJECT_REGISTRY` (`lib/subject-session.ts`).

**Subject slug** — the URL-safe identifier for a subject. Core slugs:
`mathematics`, `english`, `kiswahili`, `environmental`, `creative`, `cre`,
`indigenous`. Extended slugs: `blockchain`, `financial-literacy`, `ai`.

**Socratic mode** — the default chat mode. Tutor never gives the answer
directly. Asks questions, guides reasoning. Replaced by the dynamic prompt
(Omega-aware) as of Sept 2026.

**Compass mode** — a teacher-directed chat mode. Requires a `teacherContext`
string supplied by the teacher. Prompt built by `buildCompassSystemPrompt()`.
Used for in-class directed activities.

## Teacher Tools

**Phase 2 dashboard** — the advanced teacher analytics view
(`components/teacher/phase2-teacher-dashboard.tsx`). Shows misconceptions,
interventions, competency trends, and (as of Sept 2026) subject session
summaries.

**Misconception** — a detected incorrect mental model in a student's responses.
Stored in the `misconceptions` table with severity and confidence.

**Intervention** — a teacher action triggered by a student struggling.
Stored in the `interventions` table.

**Scaffolding level (teacher view)** — the last `scaffoldingLevel` persisted
to Redis for a student in a given subject. Visible in the Subjects tab of the
student detail view. Tells the teacher whether the AI is treating the student
as Independent, Guided, or Intensive.

**Scheme of work** — see Curriculum section above.

## Infrastructure

**Supabase** — the primary database, auth, and realtime layer. Postgres with
RLS. All student data, teacher data, chat history, progress, and XP live here.
Project: `tumikgwhrbvirpjswlzh.supabase.co`.

**Upstash Redis** — session cache. Stores `LearningSession` per user with a
7-day TTL. Used for cross-device resume points and scaffolding level. Accessed
via `lib/session-persistence.ts` and `/api/session/sync`.

**Groq** — default LLM provider for chat (`llama-3.3-70b-versatile`).
Switchable to Gemini via `LLM_PROVIDER=gemini` env var.

**Rust service** — `rust-service/` wraps `rust-core/` as an HTTP service
(`GET /health`, `POST /v1/adaptive-question`). Not yet deployed. Next.js uses
it only when `SYNCSENTA_RUST_ADAPTIVE_URL` is set; falls back to the TypeScript
Omega agent otherwise.

**AI agents backend** — Python FastAPI service on Render
(`syncsenta-ai-agents.onrender.com`). Handles curriculum transpilation,
lesson architect, and training data generation.
